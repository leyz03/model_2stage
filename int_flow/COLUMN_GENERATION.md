## 1. 列和受限问题

- **列：** x[e, t]，e = (i, j, k) 是允许的三元组（节点 i 的工人做任务 jk，ir_jk ≥ d_ij + c_jk）。
  n = 30、价格 4：每期 4,310 个，T = 100 共 431,000 个。
- **受限问题：** 完整的 tier 模型，行和其他变量都在，只把未激活的 x 上界设成 0。
  - 所以它是原问题的限制：它的可行解对原问题可行，它的 LP 值 ≤ 全量 LP 值。
- **定价：** 不解定价子问题。行都在模型里，LP 解完直接读未激活 x 的 reduced cost。
- **初始列（`init = :d0`）：** d_ij = 0 的三元组，即工人就在任务的起点，每期 620 个（14%）。
  `init = :all` 一开始就激活全部列，只用于 `--method lp --stab lazy`（全量 LP 上的行生成）。
- **初始解：** `nothing_start!`（不发任务）。它在受限问题里可行，它的值是 LB 的起点。

## 2. 流程

```
建模（完整 tier 模型）→ 未激活 x 的上界设 0 → 放松全部整数约束
│
├─ LP 段（循环）
│    解受限 LP，读未激活 x 的 rc
│    ├─ 有 rc > 1e-6 的列 → 全部激活（activate!），primal simplex 从旧基接着解 → 下一轮
│    ├─ 没有列，但有违反的稳定匹配组（只在 --stab lazy）→ 加这些组的行，dual simplex 重解 → 下一轮
│    └─ 都没有 → LP 段结束：UB = 这时的 LP 值 = 全量 LP 值
│
├─ 恢复全部整数约束（x、β、z，以及 Ycum、Yod、YU、L、I、rA、m̂、M、m̃）
│
├─ fix 步（--fixstep 1）：三级，每级是一个 MIP，时限 600 s
│    :all → :zero → :face；某一级 LB 达到 UB → 停，最优
│
├─ 受限 MIP：只用激活的列，用剩下的时限
│    LB 达到 UB → 停，最优
│
└─ reduced-cost fixing：激活 rc ≥ LB − UB 的列，再解一次 MIP（剩下的时限）→ 停
```

| 步骤 | LP / MIP | 模型里的 x 列 | 整数约束和固定 | 求解器设置 | 时限 | 成功条件 |
|---|---|---|---|---|---|---|
| LP 段第 1 轮 | LP | 初始列 | 全部放松 | Gurobi 默认（presolve，8 线程 barrier / 并发） | 总时限 | – |
| LP 段第 2 轮起 | LP | 加上上一轮所有 rc > 1e-6 的列 | 全部放松 | `activate!` 保住旧基，`Method = 0`（primal simplex）；加行后 `Method = 1` | 总时限 | 没有 rc > 1e-6 的列（lazy：也没有违反的组） |
| fix `:all` | MIP | LP 段结束时的激活列 | 全部整数；LP 解里取整数值的 x、β、z 固定 | `Method = −1` | 600 s | LB 达到 UB |
| fix `:zero` | MIP | 同上 | 只固定 LP 里为 0 的 x，二元变量都放开 | 同上 | 600 s | 同上 |
| fix `:face` | MIP | 同上 | 只固定 rc ≠ 0 的 x（在 LP 值上，是一个界），二元变量都放开 | 同上 | 600 s | 同上 |
| 受限 MIP | MIP | 同上 | 全部整数，不固定；前一步最好的解作初始解 | 同上 | 剩下的 | 同上 |
| rc fixing 后的 MIP | MIP | 再加上 rc ≥ LB − UB 的未激活列 | 全部整数；上一步的解作初始解 | 同上 | 剩下的 | 解完，或到时限 |

- MIP 段不再定价。从 fix 步到受限 MIP，列集合就是 LP 段结束时的激活列；之后只在 rc fixing 那一步一次性加列。没有分支定价。
- **fix 步的作用和由来（11-02，#3）：** fix 是找可行解的启发式，不影响精确性，也不改变界。
  - 松实例上 LP = MIP，界一开始就对，难的是找到值等于界的整数解（#2：full 的时间几乎都花在根节点找整数解上）。
    把 LP 解里的一部分变量钉住以后 MIP 小得多：`:all` 成功时只要 1–4 s；不带 fix 步时，受限 MIP 在 T = 50 要 31–33 s，T = 100 要 91–549 s。
  - 三级一级比一级松：越松越可能含有值达到 UB 的解，但 MIP 也越大。`:all`、`:zero` 没有保证；`:face` 在 LP = MIP 时保证含最优解（第 4 节）。
  - LP > MIP 时三级都到不了 UB，紧实例的平日全是这样。
- **为什么 MIP 段恢复全部整数约束，而不是只恢复 x、β、z（11-02）：** #2 在松实例上测过，x + 二元找整数解更慢（T = 100：431–2,758 s，全整数 347–1,215 s），所以 #3 沿用了全整数。#9 在紧实例上的结果相反（第 5 节最后一条）。

## 3. 什么时候收敛、什么时候停

- **LP 段收敛：** 没有未激活列的 rc > tol（tol = 1e-6，绝对值）；lazy 时还要 `separate_lp` 找不到违反的组。
  - 这时未激活列的 rc ≤ tol，对偶对全量 LP 可行，所以受限 LP 的值就是全量 LP 的值 UB。
  - 没有轮数上限。每轮把所有 rc > tol 的列一次加进来，个数不限。
  - **LP 段超时：** 程序报错 `cg LP: TIME_LIMIT` 退出，不写结果（#7、#9 的紧实例 T = 100）。
- **证明最优（`_proved`）：** LB ≥ UB − 1e-6·max(1, |UB|)；目标系数全是整数时，LB > UB − 1 也算。
  - UB 一直是 LP 段的 LP 值。fix 步和受限 MIP 的界只对受限问题成立，不用来证明。
  - 所以证明最优只有两条路：
    - fix 步或受限 MIP 找到值达到 LP 界的整数解，只在 LP = MIP（或差不到 1）时可能；
    - rc fixing 后的 MIP 解完，它的界对原问题成立。
- **时限：** `tl`（实验里 7,200 s）从模型建好以后算起，LP 段、fix 步、MIP 共用。fix 步每级另限 600 s，三级最多 1,800 s。
- **没证明时报的界：** min(UB, max(rc fixing 后 MIP 的界, LB))。rc fixing 那一步没有时间时，就是 UB（LP 界）。

## 4. 为什么精确

- 受限问题是原问题的限制，它的整数解对原问题可行，所以 LB 有效。
- LP 段收敛后 UB = 全量 LP 值，不小于原问题的最优值。
- fix 步的三级都是受限 MIP 再加固定，只产生 LB。`:face` 的依据：LP = MIP 时，值为 UB 的解都是 LP 最优解，rc ≠ 0 的 x 必须取同一个界，所以这一级的最优值就是 UB。
- reduced-cost fixing：在 LP 段最后的对偶下，任何 x[e, t] ≥ 1 的解，值都 ≤ UB + rc[e, t]（未激活列 rc ≤ 0）。
  所以比 LB 好的解只用 rc ≥ LB − UB 的列；把这些列都加进来再解，就是精确的。
- MIP 段恢复了全部整数约束，解的整数性不依赖 #2 的网络结论。

## 5. 实际跑出来的情况（价格 4，n = 30，tier 写法）

数字来自各作业 JSON 的 `log`。松实例：job 40749460（ρ = 1）。紧实例：平日 06-11、06-18，job 40788834（ρ = 0.5）、40788836（ρ = 0.3）。

| | 松（ρ = 1，12 组） | 紧，平日 T = 20、50（ρ = 0.5、0.3，8 组） |
|---|---|---|
| LP 段轮数 | 1–4 | 4–5 |
| 第一次加列 | T ≤ 50：0–28 列；T = 100：37–17,121 列 | T = 20：1.30–1.52 万；T = 50：3.96–5.37 万（T = 100：8.7–11.7 万，见 #7） |
| LP 段结束时激活的列 | 14–18% | 30–39% |
| LP 段的时间花在哪 | T = 100：第 1 轮 42–160 s；06-11、06-01 第 2 轮 59–63 s | 第 2 轮（大批加列后的热启动重解）：T = 50 为 679–1,295 s，第 1 轮只要 112–141 s |
| fix 步 | `:all` 10/12 组一次达到 UB；另 2 组 `:all` 不可行，06-11 T = 100 在 `:zero`、06-01 T = 100 在 `:face` 达到 UB | `:all` 全部不可行（≤ 1 s）；`:zero` 在 T = 20 找到解但到不了 UB，T = 50 到 600 s；`:face` 多数到 600 s |

- 紧实例 T = 100：LP 段第 2 轮在 2 h 内多数解不完（#7）。`--stab lazy` 让 ρ = 0.5 平日两天的 LP 段在 999–1,241 s 内结束，ρ = 0.3 只有 06-18 结束（5,847 s，第 2 轮 3,999 s）（#9）。
- 热启动慢的原因（#7 看日志）：Gurobi 收到旧基后不做 presolve，在原始模型上用单线程 primal simplex 迭代；冷启动是 presolve 后用 8 线程 barrier。
- 紧实例上 UB − LB 是 27–4,745（按最后的 LB 算），阈值 rc ≥ LB − UB 让几乎所有未激活列都过线，这一步等于解全量 MIP。
- MIP 段恢复的是全部整数约束；#9 测过只保留 x 和二元变量（x + 二元），紧实例上多数更好，但没在 `cg_solve` 里用。
